# Native Electron QA handoff

This is a test entry outside the production package. It launches the exact cloud-built Vite renderer and production main/preload/media/clipboard/updates modules. Only session authentication is mocked, after the production trusted-caller check. No real token, browser sign-in or keychain write. Fresh appData/userData/media-cache is generated in the OS temporary directory and its location printed; remove only that owned directory after shutdown.

Verify REVISION and SHA256SUMS first. The desktop package retains 0.1.11: this is a candidate QA bundle, not a release. `app/desktop-config.json` intentionally points at the synthetic API at http://127.0.0.1:4173. The web renderer is insufficient for this test; app/dist is the actual Vite output.

Runtime and media binaries are delivered separately with provenance/hashes. On the Mac verify Electron's downloaded archive against official SHASUMS256.txt, extract it preserving the app bundle, and run `codesign --verify --deep --strict --verbose=2 Electron.app` and `codesign -dv --verbose=4 Electron.app`. Record signature identity/TeamIdentifier and architecture. Run `file`, SHA256 and `codesign --verify --strict --verbose=2` for both media binaries. Do not remove quarantine, re-sign or bypass a signature failure silently; report it to the parent. Cloud cannot certify Darwin signatures. Use the approved runtime path only after these checks and the shared resource slot is assigned.

From the handoff directory:

1. Start `node fixtures/server.mjs` in the assigned slot (port 4173). This fixture serves only legal synthetic media/API responses. Check the port is available first; never kill an unrelated process.
2. Set `WADI_MEDIA_BIN_DIR` to the absolute directory containing the vetted Darwin arm64 ffmpeg/ffprobe. Launch the vetted `Electron.app/Contents/MacOS/Electron launch.mjs`. Optional `WADI_QA_CDP_PORT` selects an owned available port (default 9223); debugging binds loopback. Do not run production desktop dev/prepare tasks or modify global installed apps. No local build is needed.
3. The wrapper seeds qa-profile/qa-session and opens wadi://app/media/movie/qa-film?playback=qa-session. Confirm real window.wadiDesktop exists; native playback must go through preload/media IPC, HTML video/Hls.js and local FFmpeg, not MediaBunny. Native media sessions intentionally restart on changing audio; expect live position/pause continuity rather than the web decoder's no-reopen property.
4. Measure actual 440→880→440→880 Hz effect for English/Japanese/Default/repeated choices. Record local FFmpeg session behavior and playing/paused position retention, volume/mute/speed. Test paused at 65 seconds and resume. Physical speaker listening or an authorized audio capture is needed for output acceptance; labels alone do not pass.
5. Confirm rendered ENGLISH QA CAPTION / FRENCH QA CAPTION / off / on repeatedly via the real native resource proxy. Test keyboard menus, Escape/outside close, fullscreen, reload preference, failed HTTP subtitle rendering separately. Retain console errors and HLS/native failures.
6. Pointer click and keyboard Enter Copy stream link: require OS clipboard to equal exactly http://127.0.0.1:4173/multitrack.webm?token=synthetic-only&source=1. Navigate within trusted wadi origin to /media/movie/qa-film?playback=qa-session-b; real reload must preserve seed and copy source=2. Read OS clipboard using the authorized main-process probe or pbpaste. The browser's clipboard permission remains denied by design; success must use copy-stream-link IPC. Programmatic calls without user activation must reject. Real keyboard/pointer activation is a runtime gate.
7. Test native write rejection separately if supported, preserving the normal real-copy evidence; require selectable exact URL and Close. Do not replace media or clipboard handlers during the successful path. Production permissions/trusted sender policy must remain unchanged.
8. Shut down the owned Electron process and fixture server, confirm ports released, remove only printed isolated QA directory, retain logs/screenshots/audio/clipboard evidence and failed attempts. No installer, merge, release or publication action.

Record all unsupported checks honestly. Official runtime provenance is not packaged release acceptance or notarization. The fixture API is mocked; authentication and live providers are untested.

## Known binary architecture mismatch

The pinned ffprobe-static@3.1.0 npm tarball passes its registry integrity check, but `package/bin/darwin/arm64/ffprobe` is actually an x86_64 Mach-O binary. SHA256: `5b592e56f87ff754d94dadf99f38b4d0fb7d463eb780b50e0ca061d668d0e3f7`. Production packaging selects that exact path. Do not describe it as arm64 or install Rosetta implicitly. The runtime handoff retains this original as `production-media/ffprobe`; use only if the QA owner confirms an already available compatible runtime and signature checks pass.

A separately identified true arm64 ffprobe from eugeneware/ffmpeg-static b6.1.1 is supplied in `arm64-media` alongside the production-pinned ffmpeg from the same release. Its SHA256 is `bb2db6f5d8cef919da12fbf592119a987202a8c060a886f3cab091f9cab90b64`. This is an explicit test media-binary override, not the packaged ffprobe-static dependency. Parent must approve compatibility/use; successful testing with it does not certify the original packaged binary. No production dependency or binary path was changed by this hotfix.

Bridge contract: `window.wadiDesktop.copyStreamLink(url): Promise<void>` invokes only `copy-stream-link` after active user interaction. Main accepts one bounded HTTP(S) URL without credentials/whitespace/control characters from the owned window's exact wadi://app/ main frame, then writes original URL text to Electron clipboard. Clipboard reads and arbitrary IPC are not exposed; global browser permission callbacks remain fullscreen-only.
